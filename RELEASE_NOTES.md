# SWAMY Release Notes

## 2.6.4.3 (unreleased)

Branch: Version_2_6_4_0. Fixes found during SWAMY #2 IOPQ (PVP-102-014-042 Rev C).

### Fixes

- **Sort timeout no longer records an unsorted cylinder (SR-03 to SR-05).** After a sort timeout and supervisor password, the cylinder is discarded: it is not added to the bag, not written to the data file and not counted. The operator is told to rescan, and the rescan no longer raises a duplicate SN error. The password allows 6 attempts; on the 6th wrong entry the bag is closed with the message "Incorrect password entered 6 times. The bag will be closed."
- **Wrong gas serial number is sorted to the bad bin, logged and counted (SR-07, SR-08).** A serial number whose first digit does not match the lot gas type (1 = SF6, 2 = C3F8) shows "Incorrect Serial Number. Halt Production to Investigate" and a red HALT on the screen, opens the bad part chute and waits up to 15 s for the drop. No pop-up is shown during the wait, so a drop cannot be missed. On the drop, a data file line (SN, "Wrong Gas") is written and the bad count goes up by 1; then a pop-up, the supervisor password, the chute closes and SWAMY returns to Scan. The cylinder is not weighed. The handling runs only in the Scan step, not on other focus changes.
- **Wrong gas cylinder not dropped (SR-10).** If no drop is seen within 15 s, the chute closes, the pop-up adds "Wrong gas cylinder not in bad bin", and the supervisor password is required. A line (SN, "Wrong Gas - Not Sorted") is written; the bad count is not changed.
- **Duplicate serial number is sorted to the bad bin, logged and counted (SR-06, SR-11).** In both first-weight and post-weigh, a SN already in the bag shows the duplicate error, opens the bad part chute and waits up to 15 s, as for wrong gas. On the drop, a line (SN, "Duplicate SN") is written in scan order and the bad count goes up by 1. With no drop, the chute closes, the pop-up adds "Duplicate SN cylinder not in bad bin", a line (SN, "Duplicate SN - Not Sorted") is written and the bad count is not changed. The duplicate is not weighed. Previously the chute stayed closed and nothing was logged.
- **First instance of a duplicated SN is marked (SR-12).** First-weight: the first instance keeps its real first weight (previously overwritten with -20) and its line gets a third column "Duplicate SN"; at post-weigh it is rejected with reason "Duplicate SN". Post-weigh: recorded lines are never rewritten; a marker line (SN, "Duplicate SN - First Instance", blank weights and Disposition) is appended once per SN. Counts are not changed and SWAMY gives no instruction to move the part.
- **Logged lines do not count as parts (SR-13).** Wrong gas and duplicate lines (and post-weigh marker lines) have blank weights. They are not read as first weights, do not count toward the parts expected at post-weigh, and are excluded from the resume count, so the post-weigh bag still closes on its own after the last real part. A first-weight file with no part lines now loads without a software error.
- **Supervisor password limit at every prompt (SR-14).** The wrong gas and duplicate prompts now behave like the sort-timeout prompt: 6 attempts, attempts remaining shown after each wrong entry, and on the 6th "Incorrect password entered 6 times. The bag will be closed." and the bag closes. Cancel or blank counts as a wrong entry. Previously these two prompts repeated until the right password was entered.
- **Empty serial number no longer causes a software error (SR-09).** Shows "No Serial Number Entered".
- **Weight capture threshold units corrected.** The scale reading had to exceed Min Weight - 2 x Re-tare Limit before a weight was recorded, but the Re-tare Limit (entered in mg) was used as grams. The threshold was 0.6 g below Min Weight at the default 0.3 mg Re-tare Limit; it is now 0.0006 g below, matching the taring check.
- **Post-weigh bag closes on its own after the last part (SR-15).** The count that closes the bag now goes up only when a part listed in the first-weight file is recorded after its drop. A sort-timeout discard, a logged line or a serial number not in the first-weight file no longer advances it. Previously the count went up at the serial number lookup, so a part rescanned after a sort timeout was counted twice and the bag closed early.
- **Archived first-weight file is not overwritten (SR-16).** If Archived already holds the selected first-weight file, post-weigh shows "A first-weight file for this batch and bag has already been archived. Use a new batch name." and changes no file. Previously this raised a software error.
- **Post-weigh no longer resumes a bag (SR-17).** If a Completed file already exists for the batch and bag, post-weigh shows "Post-weigh has already been started for this bag and cannot be resumed. Use a new batch name." and changes no file. The "Existing Progress Found" resume prompt is removed.
- **Pre-weigh cannot reuse a batch and bag (SR-18).** Pre-weigh shows "Batch and bag already used. Use a new batch name." if In Process holds a first-weight file for the batch and bag on any date, or Completed or Archived holds one for the same date. No file is created.
- **Exact batch and bag matching (SR-19).** A first-weight file is selected only when its name parses (from the right) to exactly the batch and bag entered, ignoring letter case and leading and trailing spaces. Batch A1 no longer matches A10, batch A no longer matches A_1, and a bag no longer matches a date that contains it. More than one match shows "More than one first-weight file matches this batch and bag. Contact Supervisor." A missing In Process folder is treated as "not found" instead of causing a software error.
- **Unrecognized file in In Process (SR-20).** If In Process holds another file named for the batch and bag that is not a first-weight file for a different batch and bag (for example a renamed copy), post-weigh shows "Unrecognized file for this batch and bag in In Process. Contact Supervisor." and changes no file.
- **Refused starts return to batch selection.** After any of the refusals above (and "Invalid Batch and Bag Combination Entered"), the process and gas buttons are re-enabled and the batch and bag labels are cleared.

### Behavior changes to note for validation

- **Data file formats (SR-12, SR-13).** First-weight (In Process) file: normal lines are unchanged (`SN, wt`); the first instance of a duplicate is `SN, wt, Duplicate SN`; logged lines are `SN, , <text>`. Post-weigh (Completed) file: logged lines counted bad ("Wrong Gas", "Duplicate SN") are `SN, , , , False, <text>`; "Not Sorted" lines, which are not counted bad, are `SN, , , , , <text>` with a blank Disposition, like the marker `SN, , , , , Duplicate SN - First Instance`, so totalling the Disposition column matches the bad count. First-weight files written by 2.6.4.2 still load; a -20 first weight is still rejected "Incorrect Serial Number".
- **No sorter attached.** Wrong gas and duplicate scans skip the drop wait and are treated as dropped (logged and counted bad), as for normal sorts. The IOPQ always runs with the sorter attached.
- **First-weight logged lines are written at bag close**, like all first-weight lines. A password lockout closes the bag, so the lines are written; a software crash before bag close loses them, as today. Post-weigh lines are written at once.

- A part lighter than Min Weight - 2 x Re-tare Limit is not recorded; SWAMY stays at "Place" with no message. After the units fix this is effectively anything below Min Weight, so such parts are no longer rejected as "Too Low".
- PVP-102-014-042 Att. 16 simulates a bad part with a 2 g weight and Min Weight set to 3.0 g. The 2 g weight is not recorded under either the old or the new threshold, so that step needs a protocol redline (for example, lower Max Weight below the cylinder weight so a real cylinder is rejected as "Too High").
